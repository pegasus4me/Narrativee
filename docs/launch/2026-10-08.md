# Narrativee beta — Thursday, October 8, 2026

## Launch decision

Initial core value: one person briefs a coordinated creative team of AI agents. Brand teams are the intended audience. Human teammates sharing permissions and live editing are a subsequent scope; this release has one authenticated owner directing the agents.

Studio keeps the existing editable canvas, private uploads, saved conversation, Brand Brain and campaign generation. The layout follows the Orbit reference: main workspace on the left, agents and conversation on the right. Canvas, Brand Brain and Research are workspace views.

## Complete first-use loop

Try Narrativee → signup → enter business website → brand scan and competitor selection → review Brand Brain → add approved rules, logo, product images and inspiration → enter Studio → select social platforms and output sizes → brief the team → review every proposed output → explicitly approve creation → edit, save, reopen and export the selected social/ad images.

Manual brand setup remains available when there is no website. A failed scan must expose a retry; scan evidence is not approved identity. Competitor research can be completed later without blocking an otherwise usable creative brief.

Onboarding has three visible steps: Your website → Review your brand → Add materials. Brand review and uploads are separate screens with one primary next action. Competitor comparison is optional. Failed scans allow manual setup, failed context loads offer a retry, and continuing waits for context loading and image saves.

Keep this workflow fixed through the beta. Paid campaigns should point to the working product after production verification. Track onboarding progress and completed creatives, then use observed drop-offs, usable output and repeat briefs to guide iteration.

## Agent responsibilities

- Scout / Research: scans website context during onboarding; for a creative request, produces a structured, evidence-grounded angle and limitations that Pixel receives.
- Pixel / Creator: builds an editable composition using the brief, research handoff, approved rules and actual images; refines against review feedback.
- Sage / Brand & direction: routes the brief, checks grounding, brand fit and specificity, and requests refinement when necessary.

Agent activity comes from real server steps, with working, completed and failed states. Agents are coordinated in a bounded sequence; this does not claim autonomous background monitoring. Existing-layer revisions are manual in this first version.

Users can mention Scout, Sage and Pixel with `@` to bring their contributions into the current chat. Replies retain each contributor's identity. Agent consultations and visual proposals do not constitute human approval: the user must approve a saved proposal before artwork or logo geometry is generated. Requesting changes requires a fresh proposal; pending decisions survive reopening.

The current competitor source is website analysis. It cannot show which ads are running or converting. A live ad-library integration is still needed to establish ad activity, and connected account performance is needed for conversion evidence. Do not publish “scans what converts” as a shipped capability.

## Release gates

- Signup/signin land in Studio and a new account has a visible first-brand setup.
- A website scan populates reviewable Brand Brain findings, with retry and manual recovery.
- Uploaded materials and approved rules reach generation; agents cannot change Brand Brain implicitly.
- Scout's structured handoff reaches Pixel; Sage checks the actual plan; failed steps preserve the brief and surface an error.
- Visual creation waits for explicit human approval of the saved proposal, including requests made through agent mentions. Approval, decline and requested changes persist correctly; agents cannot approve on the user's behalf.
- Rendering and the first canvas save finish before the client calls generation successful.
- Existing canvas work survives another generation; edited work survives reopen and exports correctly.
- Verify representative real creatives, not only mocked provider responses.
- Set an explicit beta generation allowance and check cost per completed creative before public launch.
- Production URL and API are released together; local tests are not a deployment confirmation.
